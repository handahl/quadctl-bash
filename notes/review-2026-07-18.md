## 3. Skill audit — quadctl-bash vs bash-script skill

**Where the code is good (better than any archive generation):**
logs-to-stderr/data-to-stdout discipline, XDG fallbacks, NO_COLOR/TTY handling on fd 2, delegation posture in logs.bash (documented journalctl flags), three-layer drift model in matrix, pure-bash `systemctl show` parsing (no process-per-unit), ANSI-aware column padding. shellcheck: only 10 warnings (7× SC2155, 3× SC2206) — near clean.

**Hard-rule violations:**
1. **Version chaos.** `Q_VERSION="0.13.0"` vs per-file headers claiming 1.0.0 / 10.5.0 / 10.6.1 / 11.1.0 / 11.8.0, plus `AUTHOR: SAC-CP (v2.1)` and DATE fields. Skill: no hand-maintained version strings; git is the version of record. Fix: delete all per-file VERSION/DATE/AUTHOR lines; keep one `Q_VERSION` (ideally `git describe --tags` with fallback); tag the repo and stop hand-numbering.
2. **Two header styles.** New han-sh style (shim, env, control, logs, help) vs old boxed style (everything else). Finish the migration to one.
3. **Dynamic command as string:** `rsync $rsync_opts` (deploy.bash:144, 176). Skill rule 13: build as array. Related hazard: `--delete` with an empty/unmounted source dir would wipe the runtime dir — add an empty-source guard (refuse when the source contains zero quadlet files).
4. Minor: missing `--` before user-supplied paths (`mv` in migrate.bash); `set -e` + `((var++))` post-increment fragility in deploy's audit (survives only because it's called in an `if !` context).

## 4. Behavioral bugs (verified in current source)

1. **Generator errors invisible** — deploy.bash:161–164 pipes generator output through `search_pattern`, which uses `rg -iq`/`grep -Eiq` (quiet: exit code only, prints nothing). "quadlet generator reports issues" with no issues shown — the exact complaint recorded in `0000-01-to-do.md`, still unfixed.
2. **Dead stage-4 validation** — deploy.bash:176 runs the `--itemize-changes` rsync *after* the real sync already applied, so it reports nothing and the per-file generator check never fires. (The shim's `dr` command carries a working copy of the same check — dedupe.)
3. **Matrix health fallback broken** — matrix.bash:305 reads `$Q_CONFIG_DIR/${clean_name}.container` (prefix already stripped); deployed files are prefixed, so the path never exists → "n/a" instead of inactive/starting.
4. **Routing column reads the wrong label** — matrix.bash:329 queries `org.hanlab.routing`; fleet standard (homelab-quadlet skill) is `org.quadctl.routing`. Column silently degrades to ports.
5. **Silent fallback in identity resolution** — control.bash `resolve_unit_name` falls back to the bare unit name without warning. Constitution: `forbidden: silent fallback`, `ambiguity: hard-fail`.
6. **Two divergent audits** — deploy.bash `audit_directory` vs audit.bash `execute_audit`: different checks, different secret regexes, different failure posture. Constitution says advisory findings must warn, never block alone; deploy's audit blocks. Consolidate into one sourced module honoring the warn-don't-block posture.
7. **`cat intent` terminology inversion** — interact.bash "Intent View" reads `Q_CONFIG_DIR` (deployed) while README defines Intent = `Q_SRC_DIR`. `edit intent` uses `Q_SRC_DIR`. Same word, two directories.
8. **depends-on / depended-by flawed** (per notes.md) — grepping `list-dependencies` output destroys tree semantics and pulls in timers.target members. Align with the soft-wrapper posture: delegate with pass-through flags.
9. **Default prefix mismatch** — env.bash defaults to `homelab-`; the fleet uses `hanlab-`. notes.md already concludes the prefix should be `hanlab` everywhere → make it the default and much of the warning machinery can go.
10. Fossil: deps.bash:142 `return 0   # ← add this` — an AI instruction pasted into the code.

## 5. quadctl-go verdict

Abandon as a codebase; keep as an experiment record.
- Generated by qwen (see merge commits); its reconciler uses fuzzy `strings.Contains` matching — violating the "ambiguity = failure" rule its own ASSESSMENT.md acknowledges.
- ROADMAP (multi-host, rolling updates, plugins, backup/restore) reproduces the documented Phase-1 bloat pattern inside the constitution's Out of Scope list — in a language the operator can't audit.
- No Go toolchain on the host; builds need distrobox.
- Salvage: `quadctl_spec.sh` (normative spec), the ASSESSMENT's honest gap list, and the idea of build-time version stamping via `-ldflags`.

## 6. Decision: stay in bash, tie it down

Rationale: quadctl is a thin composition layer over systemctl/journalctl/podman-socket. Its open problems (§4) are delegation and consistency problems, not language problems. Go pays off when you *reimplement*; the constitution forbids reimplementation. Revisit Go only if a real TUI, the yaml manifest generators, or multi-node ever leave Out of Scope.

**Tie-down sequence (each step small, classifiable, reviewable):**
1. *Governance restore* — ai.restraints.md to root + change-protocol section + Known Gaps as the only backlog.
2. *Version discipline* — strip per-file versions, one header style, `Q_VERSION` from git tag, tag now.
3. *Bug fixes* — §4 items 1–4 first (all Narrowing/Refactor class).
4. *Test spine* — bats-core tests for the pure functions (`vercomp`, `_quadlet_disk_service_name`, `_unit_drift_state`, `resolve_unit_name`, audit on fixture files). This is the enabler for AI-assisted change without authority leakage, and the executable spec for any future port.
5. *Lint gate* — shellcheck (+ optional shfmt) via pre-commit hook or forgejo runner.
6. *Then* the wishlist under the change protocol: restart-loop detection (td3), matrix cleanup command (td6), soft-wrapper pass-through for status/deps, `--json` output for matrix.
